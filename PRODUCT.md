# Sanborn

<!-- impeccable:product-schema 1 -->

## Platform
web

## Users
Developers evaluating Sanborn's proposed agent-harness architecture.

## Product Purpose
Explain how a pure-Rust runtime and core Laya typed decisions could reduce unnecessary reasoning turns while preserving correctness.

## Capabilities and Constraints
The Three.js frog landing is live. The first runnable Rust slice provides `sb init`, `sb -p`, private user configuration, environment/keyring credential access, an Azure chat adapter, bounded plans, a required local Laya evaluator, guarded file tools, terminal color/ASCII feedback and metadata events. Caching, streaming, shell isolation and learned decision inference remain proposed. No comparative performance results establish the "fastest" positioning.
Laya's first implementation uses exact local evidence guards, not a learned model or calibrated confidence. Backend embedding remains undecided. Live inference checks use synthetic fixtures only; work data requires separate egress approval.
Read-only tadpoles use the same required Laya loop with bounded concurrent groups, per-worker limits, a shared inference budget and structured noncertified croaks. Children cannot write or recursively delegate. Diagnostics and JSON automation are implemented; neither delegation nor Laya has a demonstrated comparative speedup.

Scouts and test analysts can submit structured findings with observation/inference kinds and scoped line ranges. Rust attaches exact excerpts from successful reads, rejects supplied mismatches and stale files, and Laya gates typed citation evidence. Final JSON exposes actual parent-visible croaks. Citation integrity is not semantic certification: statements remain model-authored, and missing/rejected findings remain explicitly unverified. Synthetic acceptance checks require exact fixture citations and test properties, not just successful delegation or persuasive prose.

Parents can declare immutable citation subjects: Rust fixes the required IDs, kinds, paths and ranges; the child submits statements only. Missing or extra subjects and reference overrides fail, and incomplete required subject sets block a croak. Azure planning uses strict per-tool input schemas with parallel model function calls disabled; Rust retains authority over bounds, permissions and evidence. This requires a deployment/API supporting strict function calling, without an automatic non-strict fallback.
Built-in repository-scout and test-analyst contracts execute Rust-authored discovery plans before child reasoning, with typed Laya discovery guards and enforced directory scope. Contract baseline completeness does not certify objectives or measure test coverage. Specialist selection is explicit, not learned routing.
Coder contracts add read-backed, single existing-file replacement proposals (8,000 bytes per old/new body). Children never write. Typed Laya proposal evidence and Rust checks must pass before parent-only application by saved proposal ID; existing guarded writes enforce permission and stale-content checks. V1 excludes creation, deletion, multi-file patches and execution. Application is not code correctness or test certification.
